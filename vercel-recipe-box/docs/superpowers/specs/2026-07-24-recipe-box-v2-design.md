# 레시피 상자 v2 — 공개 조회 + 관리자 편집 설계

## 배경

기존 버전(`vercel-recipe-box`)은 방문자가 입장 요청을 보내면 관리자가 승인해야만 레시피를 볼 수 있는 구조였다. 이번 버전은 그 게이트를 없애고, 링크만 있으면 누구나 레시피를 바로 볼 수 있게 바꾼다. 대신 레시피를 추가/수정/삭제하는 권한은 관리자 전용 페이지로 옮긴다.

기존 버전에는 "레시피 등록은 됐는데 나중에 페이지를 다시 열면 내용이 다 사라져 있다"는 버그가 있었다. 코드를 분석한 결과, `storageGet` 함수가 **저장소 연결 실패**와 **진짜 데이터 없음**을 구분하지 못하고 둘 다 빈 값(`null`)으로 반환하는 것이 원인으로 확인됐다. Vercel KV 연결이 안 됐거나(예: preview 배포 URL이 production과 다른 환경변수를 참조하는 경우), 일시적으로 API 요청이 실패하면, 실제 데이터가 Redis에 살아있어도 화면에는 "레시피가 없어요"가 표시되어 마치 데이터가 사라진 것처럼 보인다.

## 범위

- 공개 페이지: 누구나 링크로 접속, 레시피 목록/상세 조회만 가능 (추가/수정/삭제 불가)
- 관리자 페이지(`/admin`): 비밀번호 입력 후 레시피 추가/수정/삭제 가능
- 기존의 입장 요청·승인, 초대 코드 기능은 완전히 제거
- 저장소 연결 실패와 "레시피 없음"을 구분해서 사용자에게 보여주는 에러 처리 추가
- 기존 Vercel 프로젝트(`yumigos-recipe`)와 연결된 Vercel KV를 그대로 재사용
- 사진 업로드/압축, 재료·단계 입력 폼 등 기존 UI/UX는 그대로 유지

## 아키텍처

정적 파일 기반 구조를 유지하되 페이지를 두 개로 분리한다:

- **`index.html`** — 공개 조회 페이지. 페이지 로드시 게이트 없이 바로 `recipe-index`를 불러와 목록을 렌더링. 카드 클릭 시 상세 보기만 가능(수정/삭제 버튼 없음).
- **`admin.html`** — 관리자 페이지. `site-passcode` 키가 없으면 "최초 설정" 화면, 있으면 "로그인" 화면을 보여준다. 로그인 성공 시 레시피 목록 + 추가(FAB)/수정/삭제 기능이 있는 기존 관리 UI를 그대로 사용.
- **`shared.js`** — 두 페이지가 공통으로 쓰는 로직: 저장소 통신(`storageGet`/`storageSet`/`storageDelete`), 레시피 카드/상세 렌더링, `escapeHtml`, 이미지 압축(`compressImage`), 저장소 연결 실패 배너 표시.
- **`shared.css`** — 두 페이지가 공통으로 쓰는 스타일 전체 (기존 `<style>` 블록 내용을 그대로 옮김).
- **`vercel.json`** — `/admin` 경로를 `admin.html`로 매핑하는 rewrite 규칙 하나만 추가.
- **`api/kv.js`** — 변경 없음.

## 데이터 모델

| 키 | 상태 | 설명 |
|---|---|---|
| `site-passcode` | 유지 | 관리자 비밀번호 |
| `recipe-index` | 유지 | 레시피 요약 목록 (id, title, cookTime, thumb, source, createdAt) |
| `recipe:<id>` | 유지 | 레시피 상세 (재료, 단계, 사진 등) |
| `join-requests` | 제거 | 코드에서 관련 로직 전부 삭제. 기존에 Redis에 남아있는 값은 그대로 둬도 무해하므로 별도 마이그레이션 없음 |
| `invite-codes` | 제거 | 위와 동일 |

## 저장소 연결 실패 처리 (버그 수정)

`storageGet`의 반환 형태를 `{ok: boolean, value: any}`로 바꾼다:
- 요청 자체가 실패(네트워크 에러, 5xx 등)하면 `{ok:false, value:null}`
- 정상 응답이지만 값이 없으면(404 등) `{ok:true, value:null}` — 이 경우가 "진짜 데이터 없음"

레시피 목록을 불러오는 함수는 `ok:false`일 때 빈 목록이 아니라 **"저장소 연결에 실패했어요. 새로고침 해보세요."** 배너를 화면 상단에 표시하고, 목록 렌더링은 건너뛴다. `ok:true`이고 값이 없을 때만 기존처럼 "아직 레시피가 없어요" 빈 상태를 보여준다.

## 관리자 페이지 동작

기존 `index.html`의 관리 관련 로직(레시피 추가/수정/삭제 폼, 사진 업로드, 비밀번호 변경)을 그대로 `admin.html`로 옮긴다. 달라지는 점:
- 입장 요청 관리(🔔), 초대 코드 생성 UI와 관련 로직 전체 삭제
- 게이트 화면에서 "입장 요청", "초대 코드" 관련 패널 삭제 — "최초 설정"과 "관리자 로그인" 두 화면만 남김
- 로그인 성공 시 바로 레시피 관리 화면(목록 + FAB + 수정/삭제)으로 진입

## 공개 페이지 동작

- 페이지 로드시 바로 `recipe-index`를 조회해 목록 렌더링 (게이트 없음)
- 카드 클릭 → 상세 보기 (재료, 단계, 사진, 출처) — 수정/삭제 버튼 없음
- 검색 기능 유지
- 저장소 연결 실패 시 위에서 정의한 배너 표시
- **`index.html`에는 관리자 로그인 버튼/링크가 전혀 존재하지 않는다.** 관리자 진입 경로는 `/admin` 주소를 직접 아는 사람만 사용하며, 공개 페이지의 어떤 요소(아이콘, 링크, 숨겨진 버튼 등)도 `/admin`으로 안내하지 않는다.
- 링크를 전달받은 방문자가 공개 페이지에서 할 수 있는 행동은 **레시피 목록 검색 · 레시피 선택해서 상세 보기**뿐이다. 그 외의 상호작용(추가/수정/삭제/설정 변경 등)은 UI 자체에 존재하지 않는다.

## 배포

기존 `yumigos-recipe` Vercel 프로젝트와 연결된 Vercel KV를 그대로 재사용한다. `배포방법.md`를 갱신해서 다음을 명확히 한다:
- 재배포시 반드시 `vercel --prod`만 사용하고 `vercel`(프리뷰) 명령은 쓰지 않는다 — 프리뷰 배포는 별도 URL과 별도 환경변수 스코프를 가질 수 있어 KV 연결이 안 보일 수 있다.
- 관리자 페이지 주소는 `https://yumigos-recipe.vercel.app/admin`

## 테스트 방법

정적 HTML/JS 프로젝트라 자동화된 유닛 테스트 대신 다음을 수동으로 확인한다:
- 로컬에서 `vercel dev`로 실행 후, 공개 페이지가 게이트 없이 바로 목록을 보여주는지 확인
- 관리자 페이지에서 레시피 추가 → 저장 → 공개 페이지 새로고침 시 반영되는지 확인
- 관리자 페이지에서 기존 레시피 수정 → 공개 페이지에 반영되는지 확인
- `/api/kv`를 일부러 실패하게 만들었을 때 (예: 잘못된 키로 강제 에러) 목록이 아니라 연결 실패 배너가 뜨는지 확인
- `vercel --prod`로 배포 후 실제 프로덕션 URL에서 위 시나리오 재확인

## 범위 밖

- 여러 관리자 계정 지원 (기존처럼 단일 공유 비밀번호 유지)
- 레시피 카테고리/태그 분류
- 검색 고도화 (재료 기반 검색 등)
